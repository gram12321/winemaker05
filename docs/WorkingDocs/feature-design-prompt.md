# Feature Design Prompt

Use this worksheet when a proposed feature needs clarification before implementation. Read the relevant design, terminology, current source, and relationship map first. Keep 04 examples separate from established 05 behavior.

## Problem and outcome

What player need or project goal does this address? What observable result should the player or caller get?

## Decisions and constraints

Which decisions are already approved? Which material choices remain open? Identify scope, dependencies, and trade-offs without assuming the application stack.

## State, interactions, and ownership

Which state is owned or derived, which actions or time steps change it, and what feedback or cross-domain relationships are needed? Consider persistence and presentation only when relevant.

## Verification and documentation

What focused scenarios or checks would demonstrate the outcome and meaningful boundaries? Which owning documents or diagrams need updates after the behavior exists?
