# Topic 08 — Bounded target interactions outside wine references

Approved 05 direction uses contextual moving targets for separate structure and taste profiles, reduces duplicate structural adjustments, and keeps physical faults distinct ([design.md](../../docs/WorkingDocs/design.md#L12), [decision 39](../../docs/WorkingDocs/design.md#L113)). Topic 08 assigns bounded contextual profiles and explanations, with no second synergy penalty ([transition-contracts.md](../transition-contracts.md#L24)). Current [types.ts](../../src/game/evaluation/types.ts) declares six structural axes and eight taste families; [MovingTargets.ts](../../src/game/evaluation/MovingTargets.ts) validates normalized values and ranges, weights axes, and returns per-axis reasons. It does not build contextual targets, and `Profiles.ts` is absent. No inspected sibling supplies a wine moving-target equivalent.

The strongest outside-wine analogues are limited. VisualIdle’s [ResearchRules.ts](C:/GitHub/visualidle/src/game/research/ResearchRules.ts#L26) validates configured definitions for duplicate IDs, missing references, cycles, invalid values and effects before use; its [research.spec.ts](C:/GitHub/visualidle/tests/game/research.spec.ts#L79) exercises those boundaries. Industri’s [qualityMath.ts](C:/GitHub/industriClicker/game/quality/qualityMath.ts#L18) returns named input, research, upgrade, production and staff ceilings plus bonuses and final output; [qualityMath.test.ts](C:/GitHub/industriClicker/tests/quality/qualityMath.test.ts#L46) checks minimum-ceiling selection and post-ceiling bonus order. Office’s [developmentEngine.ts](C:/GitHub/officetycoon/src/engine/product/developmentEngine.ts#L120) keeps feature and total bug effects at distinct scopes, while [bugEngine.ts](C:/GitHub/officetycoon/src/engine/product/bugEngine.ts#L30) owns bug generation/state. Its [developmentEngine.test.ts](C:/GitHub/officetycoon/tests/developmentEngine.test.ts#L174) checks that scope. These are validation and explainability patterns, not wine formulas.

**Proposed take:** define deterministic, independent rule deltas per target axis; sum in stable order, cap each axis’s shift budget, clamp to `[0,1]`, and preserve configured minimum width or reject impossible profiles. Return the base target, applied deltas and reason strings. Validate rule IDs, axis references, finite deltas and dependency cycles. Let target movement account for balance interactions once; diagnose physical faults separately, assigning any later quality or market consequence one explicit owner.

**Boundary scenarios:** zero/one domain edges; shift just below, at and beyond each cap; narrow ranges at both domain edges; multiple rules in reversed declaration order produce identical targets/reasons; missing/cyclic rules fail; an extreme source value cannot move its own target or erase its own fit; fault diagnosis leaves target ranges and axis fits unchanged. Existing [moving-targets.test.ts](../../tests/game/moving-targets.test.ts) covers generic fit edges, ordering and invalid ranges; profile-rule cases remain to add.
