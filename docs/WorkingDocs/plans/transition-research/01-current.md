# 01 — Current research: Vineyard characteristics

## Evidence and status

The approved 05 direction keeps vineyard and harvest as the source of wine potential, but replaces 04’s blended land-value concept with **Terroir Potential** for agricultural/raw-material contribution and **Origin Prestige** for commercial reputation. Exact site variables, equations, and catalog content remain open; decision 43 says to select 04 grapes and other authored content after the 05 mechanics exist. The accepted weekly tick updates vineyard conditions before work, applies partial-harvest output at week end, and starts new lots developing in the next interval. See [design.md](../../docs/WorkingDocs/design.md), decisions 9–10, 17–18, 23, 29, 38, 40, and 43.

There is no 05 vineyard or work implementation yet. [CompanyState.ts](../../src/game/core/CompanyState.ts) owns only the calendar; [AdvanceTime.ts](../../src/game/simulation/AdvanceTime.ts) advances one week and emits a boundary event. [application-flow.md](../../docs/WorkingDocs/application-flow.md) explicitly lists weather, vineyard growth, staff work, and wine as unimplemented. The current game tests include only [time-advance.test.ts](../../tests/game/time-advance.test.ts) for this domain layer.

## Winemaker04 reference behavior (not a 05 specification)

I inspected local Winemaker04 at commit `94fd950` (the revision pinned in the architecture proposal). Its `Vineyard` type combines site identity/area (country, region, hectares, altitude, aspect, soils) with planted variety, vine age/density, health, yield factor, status, and ripeness (`C:\GitHub\winemaker04\src\lib\types\types.ts`). `calculateGrapeSuitabilityMetrics` evaluates grape against region, altitude, sun exposure/aspect, and soil (`src/lib/services/vineyard/vineyardValueCalc.ts`); `projectVineyardWeek` combines seasonal ripeness/health deltas with weather and site exposure (`src/lib/features/weather/weatherVineyardService.ts`). These are useful dependency examples, but their values and formulas should not be ported as 05 facts.

04 yield is derived from area and vine density, then multiplied by grape suitability, variety natural yield, ripeness, vine yield, and health (`src/lib/services/vineyard/vineyardManager.ts`). Planting selects a grape, initializes a planting state, grows density with applied work, then finalizes status (`vineyardService.ts`, `vineyardManager.ts`). Partial harvest derives the incremental quantity from work progress and remaining yield, limits it by assigned storage capacity, creates harvest output with vineyard/grape/date provenance, and caps applied work to what could be placed. The activity manager awards XP only for applied work. Useful precedent tests are `C:\GitHub\winemaker04\tests\vineyard\vineyardLifecycle.test.ts` (partial harvest, storage blocking, and work accounting), `yieldCalculator.test.ts`, and `grapeSuitability.test.ts`. The 04 architecture review also identifies the need to commit vineyard, work, inventory, and lot changes as one 05 transition rather than preserve 04’s separate writes.

## Minimal 05 model and checks

Keep site/vine/crop rules in a vineyard domain: planting establishes variety and density; a deterministic weekly rule consumes explicit date/weather/site inputs to update condition and harvest readiness; a work result applies only feasible planting or harvest effort. The player-facing preview and execution should use the same rules. Keep Terroir Potential on the agricultural path and Origin Prestige on the commercial path. With the planned integer-gram grape and integer-ml must/wine units, harvest should transfer only the feasible integer grams into inventory; after transfer, inventory alone owns amount and place, while a wine lot owns composition/development and retains vineyard/grape/harvest provenance. Avoid a second mutable amount in the lot. Represent any still-on-vine crop as vineyard-owned harvest availability or a derived yield entitlement, not as both an inventory holding and vineyard stock. Do not average derived characteristics to merge partial harvests as 04 does; 05’s approved physical-lot and shared-lineage rules require compatible material-state handling.

For the first 05 implementation, add focused tests under `tests/game/vineyard-lifecycle.test.ts`: site/grape potential is deterministic and separate from Origin Prestige; weekly weather/date input updates only eligible planted crops; partial harvest emits integer grams no greater than remaining crop, respects capacity and applied work, and repeated portions balance to the total harvest; preview and execution agree; a week-end lot receives no development from the interval that created it. These are proposed 05 checks, not tests run in this research pass.
