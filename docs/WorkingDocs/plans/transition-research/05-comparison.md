# Generic structural evaluator comparison

`../../src/game/evaluation/types.ts` is the only file under `src/game/evaluation`: it declares six structure axes, generic target ranges/weights/reasons, and per-axis assessment fields, but no evaluator. The approved direction in `../../docs/WorkingDocs/design.md` calls for one configurable moving-target framework for structure and taste, with distinct profiles and scoring roles; exact equations remain open. The migration row (`../../docs/WorkingDocs/Winemaker04_to_05_System_Migration_Research.md`, “Structural characteristics and moving targets”) explicitly says neither sibling is a wine-balance analogue. The transition overview also warns that target shifts need bounds so extreme values cannot excuse themselves.

Useful implementation precedent is Industri Clicker’s pure `calculateOutputQuality` in `C:/GitHub/industriClicker/game/quality/qualityMath.ts` (inspected at `a6c85c0b6d3b832c3a23829a134d049ecef01bbc`). It returns named ceilings, the selected minimum, bonus, multiplier, and final output in one breakdown. Its tests at `C:/GitHub/industriClicker/tests/quality/qualityMath.test.ts` verify weighted inputs, each limiting factor, absent inputs, and post-ceiling adjustments. This is a good precedent for traceable intermediates and edge-case contracts, but it is scalar commodity quality, not target-fit scoring.

Office Tycoon’s `calculateSoftwareQuality` in `C:/GitHub/officetycoon/src/engine/product/developmentEngine.ts` (revision `1cbabbc02ea1eb2950732b81e7f2dd2561cbd0be`) deterministically combines architecture and averaged feature scores, with explicit range validation. Its invalid-input path logs a warning, and its result is only a scalar. `C:/GitHub/officetycoon/tests/developmentEngine.test.ts` checks formula composition and invalid values. Use it only as an input-validation example, not a pure or explainable evaluator pattern.

For 05, keep target construction separate from pure assessment and return the existing per-axis fields plus enough named intermediates to explain aggregate scoring. Future tests should cover deterministic/no-mutation output; exact low/high and outside-range fit; visible weights reproducing a bounded 0–1 score; invalid/non-finite or reversed ranges; and capped target movement under extreme inputs so a profile cannot excuse itself. These are proposals, not approved equations or checks run here.
