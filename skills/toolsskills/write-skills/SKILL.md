# Write Skills

A skill captures reusable non-obvious guidance, not one solved task or project history.

1. Identify the behavior gap, triggers, target users, and use cases.
2. Keep `SKILL.md` concise: purpose, when to use or avoid, constraints, workflow, and verification.
3. Add references or scripts only when they provide maintained task-specific value.
4. Keep skills stack-aware but avoid duplicating root project rules.
5. Validate frontmatter, paths, trigger specificity, stale assumptions, and real pressure scenarios where practical. Run changed executable helpers against meaningful examples and preserve relevant source attribution.

Use lowercase hyphenated names. Preserve user intent and authorization boundaries; a skill must not broaden permission or turn a project convention into a universal rule.
