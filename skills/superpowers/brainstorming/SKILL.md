# Brainstorming

Use for deliberate design exploration, not routine implementation.

1. Read the relevant project context and current source. Distinguish the 05 direction from 04 examples and unimplemented proposals.
2. State the decision and confirmed constraints. Check the actual stack rather than assuming TypeScript, React, PixiJS, or a backend is already selected.
3. Ask only questions that cannot be answered from available context and that materially affect the decision. Continue independent work where possible.
4. Present a small set of useful options with user impact, implementation cost, and a recommendation when a choice is needed.
5. Record durable approved choices in [design.md](../../../docs/WorkingDocs/design.md), and implemented state or interaction flow in [application-flow.md](../../../docs/WorkingDocs/application-flow.md).

For a visual choice that is easier to understand by seeing it, use an appropriate available visualization. The optional [visual companion](visual-companion.md) carries forward the 04 local mockup tool; it does not select a 05 UI technology.
